# Bound PPT Agent — 交互流程设计

> 依据 `docs/linux-do-1782304-ppt-agent-extract.md` 中提取的原帖设计思路，进行产品化借鉴后的交互流程设计。
> 配套可点击 HTML 原型：`prototype/ppt-agent-prototype.html`（纯静态单文件，内置 mock LLM 流式返回）。

---

## 0. 产品定位

**Bound PPT**：一个"专家团队式"PPT Agent。用户只给一个主题，Agent 像真实 PPT 公司的「调研员 → 策划师 → 设计师」流水线一样跑完全程，用户在关键节点做**少量、高杠杆的确认与调整**。

### 0.1 原帖思路 → 产品落点（借鉴映射）

| # | 原帖思路 | 产品落点 |
| --- | --- | --- |
| 1 | 忘了"一键生成"，从"提问"开始；AI 像专业顾问一样需求调研 | **阶段 2 需求访谈**：先检索资料，再以选择题卡片形式追问 4 个关键问题，产出"需求画像"确认卡 |
| 2 | 先大量检索资料，大纲必须基于调研信息 | **阶段 2 右侧资料面板**：实时展示 Agent 检索到的资料源；访谈答案 + 资料摘要一起注入大纲生成 |
| 3 | 便利贴法：一页一便利贴，贴满一墙 | **阶段 3 便利贴看板**：大纲以"数字便利贴"呈现，支持拖拽排序、增删改、章节重组 |
| 4 | 策划稿（版面规划）与设计稿（风格样式）分离，重要 PPT 在策划稿阶段精调 | **阶段 4 策划稿**（灰阶 Bento 线框）与 **阶段 6 设计稿**（上风格）两阶段生成；策划稿支持逐页重跑与微调 |
| 5 | 卡片式布局（Bento Grid）是 AI 最易理解的设计语言 | 策划稿的**版式词汇表**与设计稿的**渲染器**均基于 Bento Grid 六种组合（单一焦点/两栏/三栏/主次/英雄式/混合） |
| 6 | SVG 可直接进 Office、完全可编辑；自用可选 HTML | **导出菜单**：PPTX（SVG 合成）/ HTML / PDF 三选项 |
| 7 | 全自动跑完 + 重要场合人工精调 | **两种模式**：全自动（一路确认到设计稿）/ 专家陪跑（每阶段停下确认），且任意页可单独"重新生成" |

### 0.2 用户与场景

- 主要用户：需要高质量对外演示资料的职场人（产品/市场/售前/创始人）。
- 核心场景：输入主题 → 泡杯咖啡 → 拿到一套可交付的设计稿；重要 PPT 则在便利贴/策划稿两个节点花 5 分钟精调。

## 1. 交互总览

```
┌─────────┐   ┌──────────────┐   ┌─────────────┐   ┌─────────────┐   ┌──────────────┐   ┌─────────────────────┐
│ 阶段1     │   │ 阶段2         │   │ 阶段3        │   │ 阶段4        │   │ 阶段5         │   │ 阶段6                │
│ 新建项目  │ → │ 需求调研+访谈  │ → │ 大纲·便利贴   │ → │ 策划稿·线框   │ → │ 风格选择       │ → │ 设计稿·预览与导出     │
│ 主题输入  │   │ 检索+提问+画像 │   │ 拖拽增删改    │   │ 逐页Bento线框 │   │ 风格画廊       │   │ 单页重跑/微调/导出    │
└─────────┘   └──────────────┘   └─────────────┘   └─────────────┘   └──────────────┘   └─────────────────────┘
                     ↑______________________回退（顶部阶段导航可跳回任意已完成阶段）_______________________↑
```

- **顶部全局**：Logo、项目名、阶段导航条（已完成阶段可点击回跳）、模式标签（全自动 / 专家陪跑）。
- **自动推进**：全自动模式下，阶段 2 答完访谈 → 阶段 3、4 自动跑完并在阶段 5 风格页暂停；专家陪跑模式下每阶段结束都停在"确认按钮"上。
- **回退**：任何阶段可点击顶部导航回跳已完成阶段；改动下游数据后，受影响的下游阶段标记为"待重跑"。

## 2. 阶段明细

### 阶段 1 · 新建项目（Home）

| 项 | 设计 |
| --- | --- |
| 界面 | 居中 Hero：大标题 + 主题输入框 + 场景快捷 chips（产品发布 / 融资路演 / 项目汇报 / 技术分享）+ 模式选择（默认全自动） |
| 用户操作 | 输入主题（示例"Dify 企业介绍"）→ 点击「开始生成」 |
| Agent 行为 | 无（进入阶段 2） |

### 阶段 2 · 需求调研 + 访谈

| 项 | 设计 |
| --- | --- |
| 界面 | 左侧 **对话流**（Agent 消息 + 工具调用卡 + 问题卡片）；右侧 **调研资料面板**（来源列表实时增加） |
| Agent 行为（流式） | ① 消息「我先去调研一下主题相关资料…」；② 工具卡：`web_search("Dify 企业介绍 官网")` 等逐条执行，右侧资料列表逐条点亮（来源标题 + 摘要）；③ 汇报「共找到 12 份资料…」；④ 推送 **4 张问题卡片**（单选/多选）：受众、演示目的、页数规模、风格偏好；⑤ 用户答完后输出「需求画像」确认卡（汇总所有答案） |
| 用户操作 | 回答问题卡片 → 查看需求画像 → 点击「需求没问题，生成大纲」 |
| 边界 | 问题卡片必须全部作答才能进入下一步；画像卡上支持点「补充说明」追加自由文本 |

### 阶段 3 · 大纲（数字便利贴）

| 项 | 设计 |
| --- | --- |
| 界面 | **便利贴看板**：封面/目录/结尾为独立便签，正文按「章节」分组，每页一张便签（显示页码、标题、内容要点关键词）；右上角统计「N 页 · M 章节」 |
| Agent 行为（流式） | 按 `[PPT_OUTLINE]` JSON 分块流式输出，看板上便签**逐张飞入**（对应原帖动图效果） |
| 用户操作 | ① 点击便签标题行内编辑；② 便签「+」在该章节内插页、「×」删除；③ **拖拽**便签跨章节/调整顺序；④ 确认「大纲没问题，生成策划稿」 |
| 边界 | 页数与访谈约定差异 >2 页时提示；封面/目录/结尾不可删除但可编辑标题 |

### 阶段 4 · 策划稿（版面规划）

| 项 | 设计 |
| --- | --- |
| 界面 | 左侧页列表（便利贴缩略图，按章节分组）；主区 **16:9 灰阶 Bento 线框**：每张卡片标注「此处放什么」；顶部批量生成进度条 |
| Agent 行为（流式） | 逐页生成策划：选择 Bento 版式（从六种组合词汇表中选）→ 输出卡片清单（每卡片：内容来源页要点 + 建议尺寸权重 + 建议元素类型）→ 线框动画铺开 |
| 用户操作 | ① 逐页点「重新策划」（该页换一版版式）；② 输入自然语言微调（示例："第二页把数据卡片放大，案例移到右侧"）→ Agent 重出该页线框；③ 「策划稿确认，选风格」 |
| 边界 | 未生成的页显示骨架占位；微调指令不消耗整页重跑，只影响该页 |

### 阶段 5 · 风格选择

| 项 | 设计 |
| --- | --- |
| 界面 | 风格画廊卡片（4-6 款）：每款含迷你预览图 + 色板圆点 + 适用场景说明（如"科技深色·适合发布会"） |
| 用户操作 | 单选风格 → 「开始生成设计稿」（全自动模式下可勾"记住我的偏好"） |

### 阶段 6 · 设计稿（生成、预览、编辑、导出）

| 项 | 设计 |
| --- | --- |
| 界面 | **工作台三栏**：左·缩略图列（按章节分组）；中·大画布预览当前页（16:9，Bento 卡片成稿）；右·当前页操作面板（重新生成 / 微调输入框 / 版式信息） |
| Agent 行为（流式） | 逐页生成设计：消息流显示「正在为第 N 页规划便当网格… → 应用风格「科技深色」… → 渲染完成」；右侧操作面板的版式说明同步打字机输出 |
| 用户操作 | ① 翻页（缩略图/左右键）；② 对某页不满意 → 输入微调指令或点「换一版」（mock 中轮换 2-3 个变体）→ 该页流式重渲染；③ 「导出」→ 弹出导出菜单（PPTX（SVG 合成，推荐）/ HTML / PDF）→ mock 进度 → 完成提示 |
| 边界 | 重新生成只影响单页；导出为 mock 演示（原型不真实生成文件） |

## 3. 状态机与数据流

### 3.1 前端项目状态（原型内为 JS 对象）

```ts
type Stage = 'home' | 'research' | 'outline' | 'plan' | 'style' | 'design';

interface ProjectState {
  topic: string;
  mode: 'auto' | 'guided';
  stage: Stage;
  research: { sources: Source[]; questions: Question[]; answers: Record<string, string> };
  requirements: { audience?: string; goal?: string; scale?: string; style?: string };
  outline: { cover: PageRef; toc: PageRef; parts: { title: string; pages: PageRef[] }[]; end: PageRef };
  plans: Record<pageId, { layout: BentoLayoutName; cards: PlanCard[]; status: 'idle'|'streaming'|'done' }>;
  styleId?: string;
  slides: Record<pageId, { variant: number; status: 'idle'|'streaming'|'done' }>;
}
```

### 3.2 Mock LLM 返回契约（原型内置三条流式模拟器，与提示词对应）

| 阶段 | 模拟器 | 事件序列（SSE 风格） |
| --- | --- | --- |
| 需求调研 | `mockResearch()` | `{type:'message',delta}` → `{type:'tool',name:'web_search',query}` ×N → `{type:'source',...}` ×12 → `{type:'questions',items}` |
| 大纲 | `mockOutline()` | `{type:'outline_delta',chunk}`（模拟 `[PPT_OUTLINE]` JSON 分块，增量渲染便签） |
| 策划/设计 | `mockPlan(page)` / `mockDesign(page,variant)` | `{type:'page_start',pageId}` → `{type:'card_delta',...}` → `{type:'page_done'}` |

> 原型中所有"打字机"效果均由定时器切片实现，模拟真实 LLM token 流；不发起任何网络请求。

### 3.3 借鉴自提示词的结构化约定

- 大纲 JSON 结构沿用原帖提示词 1 的 `ppt_outline`（cover / table_of_contents / parts / end_page）。
- 策划与设计的版式词汇沿用提示词 2/3 的 Bento Grid 六种组合；设计画布固定 16:9（原型用 CSS 网格模拟 1280×720 viewBox 语义）。

## 5. 原型实现说明

- 单文件 `prototype/ppt-agent-prototype.html`：纯 HTML/CSS/JS，无构建、无外部依赖、无网络请求。
- Mock 数据内置在 `MOCK` 常量区（主题、调研来源、访谈问题、大纲 JSON、策划与设计稿变体），对应示例主题"Dify 企业介绍"。
- 流式模拟器：`stream(text, onChunk)` 定时切片打字机；生成类阶段用阶段粒度的调度器串行推进。
- 设计稿渲染：CSS Grid 实现的 Bento 版式渲染器（`bento-single / bento-2col / bento-3col / bento-hero / bento-mix` …），4 套风格主题用 CSS 变量切换。
- 视口：桌面优先（≥1200px 三栏），窄屏自动降级为单栏纵向流。
